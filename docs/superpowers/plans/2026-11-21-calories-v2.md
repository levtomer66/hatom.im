# Calories v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (owner chose Native for v1; same here). Steps use `- [ ]`.

**Goal:** search bar + ארוחה button, current-meal highlight, workouts as burned kcal, weight shared with /workout, recommended goals.

**Architecture:** pure rules in `src/lib/calories/calories.ts` (import-free, `node --test`); Mongo glue in `src/models/Calories.ts` (reads `workouts` and `workoutUserSettings` via the native driver / `WorkoutUserSettings` helpers); routes under `src/app/api/calories/`; UI in `src/app/calories/`.

**Spec:** `docs/superpowers/specs/2026-11-21-calories-v2-design.md` (on top of `2026-11-21-calories-design.md`).

## Global Constraints

- `src/lib/calories/*.ts` stays import-free; tests import with `.ts`.
- Node at `/opt/homebrew/bin/node`; dev server `npm run dev:local -- -p 3250` (launch config "calories"), Docker Mongo :27018.
- Never write the `workouts` collection. Weight lives only in `workoutUserSettings.bodyweightKg`.
- Bounds: weight 25–400 kg; burned 0–3000; birthYear 1920…(year−13); height 120–230; activity ∈ {1.2,1.375,1.55,1.725}.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; `--no-verify` only after tsc + lint + tests pass by hand.

## Review Focus

1. A goal following the recommendation with no weight or no profile — must keep the last stored numbers, never NaN / 0.
2. A workout with no counted sets (all empty) → 0 kcal, still listed.
3. Weight changed on /workout, then /calories opened on a past day — no weigh-in for the past day.
4. Search results open + a sheet open at the same time (outside click, scan) — one closes the other cleanly.
5. Settings docs from v1 (goal + proteinGoal only) still parse and show.
